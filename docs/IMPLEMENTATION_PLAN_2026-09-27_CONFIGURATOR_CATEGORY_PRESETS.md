# Implementation Plan — Configurator Category Presets & Configuration Truth Restoration

**Date:** September 27, 2026
**Owner:** Kirk LaSalle · **Prepared by:** GitHub Copilot (Z.ai GLM 5.3)
**Source audit:** [`AUDIT_REPORT_2026-09-27_CONFIGURATOR.md`](AUDIT_REPORT_2026-09-27_CONFIGURATOR.md)
**Roadmap phase:** R15 — Category Gaze Profiles & Configuration Truth
**Governing directives (Kirk LaSalle, 2026-09-27):**

1. *"The presets are for baseline configurations and development"* — the five global Quick Presets are kept and re-calibrated, not replaced.
2. *"Control presets based on categories of Player and player type and race, NPCs and NPC type and race, Creatures, Animals, other, etc."* — category presets are **part of the Character Gaze Profiles system**, not a second global preset bank.

---

## Design Principles (non-negotiable)

1. **Default parity.** Every new feature disabled or neutral = bit-for-bit current behaviour. The `GazeProfile` multiplier contract (1.0 = unchanged) is the vehicle for everything.
2. **Additive only.** No existing control, preset, or key is removed. New sections and panels sit alongside.
3. **Base-form reads.** All new SDK gathers (race, keywords) read from `TESActorBase`/`TESRace` data, never actor-process dispatch — the 2026-09-25 crash lesson, now a standing rule.
4. **Sanitise everything.** Every new INI key is clamped in `Sanitise()` with a logged warning.
5. **Four-copy sync.** `TrueGazeConfig.html` changes land in root, `skyrim/`, and both `dist/` trees (or the dist trees are regenerated by the packager — see C4).

## Stage C1 — Category Gathering (engine, SDK adapter)

**Goal:** give `TemperamentInput` a category axis derived from safe, base-form reads.

- **C1.1 `GazeCategory` enum** in `CharacterProfile.hpp`:
  `Player, HumanoidNPC, Guard, Child, Vampire, Werewolf, Khajiit, Argonian, Elf, Orc, OtherHumanoid, Creature_Predator, Creature_Prey, Creature_Dragon, Undead, Daedra, Construct, OtherCreature`
- **C1.2 Gather** (in `GatherTemperament`, all null-guarded, base-form-first):
  - `IsPlayerRef()` → Player.
  - `IsGuard()` / `IsChild()` → Guard / Child (existing flags, promoted into the category).
  - `GetActorBase()->GetRace()` → race FormID; match known editor IDs (`KhajiitRace`, `ArgonianRace`, `ElfRace` variants, `OrcRace`) → race categories; unknown humanoid races → `OtherHumanoid`.
  - Race + actor-base **keywords** (`Vampire`, `Werewolf`, `ActorTypeUndead`, `ActorTypeDaedra`, `WeapMaterial*`-style construct keywords) → supernatural categories. Keyword reads are `BGSKeywordForm::HasKeyword` — data-side, no dispatch.
  - `!IsHumanoid()` → creature branch: keywords (`ActorTypePredator`, `ActorTypePrey`) and dragon race check (`DragonRace`) → predator/prey/dragon.
- **C1.3 Relationship axis re-enable (F5):** replace the hard-disabled `in.relationshipRank = 0.0f` with the proven-safe pattern from `GazeEngine::RelationshipRankForActor` (base-form `relationships` array + `BGSRelationship::GetRelationship`, full null-guard chain). Keep the historical crash comment; note the R14 E7.6 proven path.
- **C1.4 Unit tests:** extend `tests/KinematicsTests.cpp` (or a new `CharacterProfileTests.cpp`) with category classification cases: guard, child, khajiit, vampire, predator, dragon, construct, unknown-race fallback, null-actor fallback. All SDK-free (pure `Classify` with synthetic `TemperamentInput`).

**Exit:** all tests green; no SDK calls outside the adapter; default parity untouched.

## Stage C2 — Category Profile Layer (engine, pure logic)

**Goal:** per-category multiplier bundles, INI-configurable, layered onto the temperament profile.

- **C2.1 `CategoryProfileBundle`** — same multiplier fields as `GazeProfile` (aversion rate/dwell, mutual-gaze threshold, fixation scale, path randomness, mode bias, vertex weights, triangle enabled). One default bundle per category, compiled defaults chosen to express the *stereotype the category implies* (e.g. `Creature_Predator`: triangle off, fixation ×1.4, aversion ×0.3 — a stalking wolf; `Khajiit`: feline darting — fixation ×0.8, path randomness ×1.3; `Guard`: steady lock; `Vampire`: intense unblinking lock, aversion ×0.2).
- **C2.2 Application order in `Classify`:** temperament axes → **category bundle (multiplicative)** → combat state → clamps. A category bundle can zero-out or boost what temperament produced, but clamps still bound everything.
- **C2.3 INI surface — new `[Profiles]` section** (additive; absent = compiled defaults):
  - `bEnableCategoryProfiles=true` (master; false = temperament-only, exact current behaviour)
  - Per-category override keys, e.g.:
    `[Profiles]` `fGuardAversionMult`, `fGuardFixationMult`, `bKhajiitTriangle`, `fKhajiitPathRandomnessMult`, `fPredatorFixationMult`, `fVampireAversionMult`, …
  - **Design rule:** expose the *high-signal* multipliers per category (3–6 keys each), not all 16 fields × 18 categories — the configurator shows the rest via presets. Exact key list to be finalised in review with Kirk.
- **C2.4 `ConfigManager`:** read, sanitise (all multipliers clamped [0.1..3], matching the profile clamps), save, and plumb into `GazeTuning` → `GazeEngine` → the profile refresh path.
- **C2.5 Player category specialisation (player type):** the Player category bundle composes with the existing behavioural warmth blend. Add play-style bias inputs (read from equipped weapon/spell state — `ActorEquippedWeapon`/`ActorEquippedSpell` base-form reads): stealth-oriented → aversion ×1.2, fixation ×0.9 (wary, watchful); heavy combat → steady lock. Keep this **lightweight and observational** — flag for Kirk's review before tuning.
- **C2.6 Unit tests:** bundle application order, clamp integrity, default parity with `bEnableCategoryProfiles=false`, per-category stereotype sanity (predator has triangle off, vampire aversion low, etc.).

**Exit:** category behaviour demonstrable in standalone tests; parity proven.

## Stage C3 — Configurator Exposure (HTML, all copies)

**Goal:** the "Gaze Profiles" category panel + preset re-calibration.

- **C3.1 New "Gaze Profiles" panel** in `TrueGazeConfig.html` (additive, after the existing CharacterProfile row):
  - Category cards grouped as Kirk specified: **Player** (incl. play-style bias), **NPC Types** (Guard, Child, Vampire, Werewolf), **Races** (Khajiit, Argonian, Elf, Orc, Other), **Creatures & Animals** (Predator, Prey, Dragon), **Other** (Undead, Daedra, Construct).
  - Each card: the category's exposed multipliers as sliders + a "Reset category to default" button + the same rich-tooltip standard as the rest of the page.
  - A per-category **mini-preset row** (e.g. Khajiit: "Feline Curious / Default / Intense Stare") — these are the *category presets*; they write only that category's keys.
- **C3.2 Quick Preset re-calibration (F2):** re-derive all five global presets from the **v1.0.6 shipped INI baseline**:
  - Every preset's speed keys re-expressed knowing the calm/combat model (INI = combat ceiling; calm = ×0.25 at runtime). Remove the double-counted slowdown from Subtle/Intense.
  - `fHeadEngageThresholdDeg` floor at 12° in all non-developer presets (the verified anti-twitch value).
  - Developer preset aligned to the shipped INI values exactly (it is the testing baseline).
  - Each preset keeps its *intent* as a documented delta from baseline in the tooltip.
- **C3.3 DEFAULTS sync (F1):** correct the six drifted default values (`fSaccadeSpeedMult` 1.5, `fVelocitySaturation` 18.0, `fMicroJitterAmp` 0.28, `fHeadOnsetDelaySec` 0.13, `fHeadEngageThresholdDeg` 12.0, `fPupilGlowIntensity` 0.35, `bGazeRaysTerminus` true); reconcile `bEnableConsoleCommands` (document the divergence or match the INI's true).
- **C3.4 Tooltip truth pass (F9):** rewrite the stale weight recommendations in `TOOLTIPS` to the eye-dominant values.
- **C3.5 Propagate** to `skyrim/TrueGazeConfig.html` and regenerate both `dist/` copies (F8).

**Exit:** configurator writes a valid `[Profiles]` section; presets verified against the baseline; all four copies identical.
